# savakan-gg

start.gg で運用する大会を、イベント単位でローカルにミラーし、進行管理・試合結果入力・一括報告・OBSオーバーレイ連携・連絡運用まで一括で扱う Tauri アプリです。

## 概要

サバ管ggは、start.gg のイベントデータをベースとして使いながら、ローカルで追跡・検証・補助運用を行うためのアプリケーションです。  

主な目的は次のとおりです。

- OBS 向けのライブオーバーレイを組み込み、現在の試合情報と勝ち数を表示する  
  - 対戦カードをオーバーレイ表示する際のプレイヤー名入力等の煩雑さを軽減
- アイテムリスト・プレイヤー情報・配信者向けメッセージと呼び出し管理を同一イベント内で扱う
  - 他のクライアントと連携して呼び出し情報を共有、表示可能

## 主要機能

### 1. 大会・イベント同期

- tournament slug から event 一覧を取得
- direct 指定で tournament slug + event slug を引く
- event 単位でローカルスナップショットを作成・選択・更新・削除
- スナップショットを JSON ファイルにエクスポート / インポートして、別クライアントへ共有
- 同一 tournament 内で複数 event を持つ運用に対応

### 2. 大会管理

- event alias の設定
  - 日本語名のエイリアスが設定可能
- 1P/2P 判定ルールの選択
- カテゴリごとのアイテムリスト、選択数制限、重複可否の管理
  - start.ggで未対応のゲームでも使用キャラの履歴などが保持できる
  - 使用率の表示も可能
- 変更内容をイベント単位で保存

### 3. ブラケット管理

- phase / pool を切り替えて試合を表示
- Elimination はラウンド別のブラケット、ROUND ROBIN は対戦マトリックスと現在順位を表示
- 表示倍率を変更可能（ROUND ROBIN の standings は倍率の影響を受けない）
- slot ごとに 1P/2P・スコア・勝者をローカル保存
- 保留中結果と確定済み結果を分けて管理
- winner 判定が start.gg と衝突した場合は競合解消を行える
- 一括報告により複数 set をまとめて反映
- pool ごとのスコア編集ロックや、外部報告者へのスコア報告を利用可能
- 「スナップショット&メタデータ設定」の「動画チャプター生成」で、選択中イベントの配信済み Set を開始時刻順に出力できる。配信開始順の一覧から時刻合わせの基準にする試合を選択できる（初期選択は最初の試合）。基準の試合の対戦プレイヤー（1P vs 2P）・Phase／Pool／Set・ラウンド・配信開始記録時刻を表示する。動画上でその試合を探し、開始時刻（`hh:mm:ss` または `mm:ss`）を入力して右側の「テキスト生成」を押すと、記録時刻との差から1P・2Pプレイヤー名を含むチャプター文字列を生成する。動画時間が1時間未満なら時刻は `mm:ss`、1時間以上なら `hh:mm:ss` で表示する。基準の試合を変更すると入力時刻をリセットする。入力やエイリアス名の設定変更、記録の再読み込み後は再度生成する
  - 計算された再生時刻が10秒未満の試合（負の時刻を含む）は、時刻の代わりに `(未記録)` と表示する。10秒ちょうどから通常の時刻を表示し、`00:00` のオープニング行は維持する
  - `00:00` のテキストは変更可能（初期値「オープニング」）。「テキスト生成」の右にある「テキストをコピー」で生成結果をクリップボードへコピーできる
  - 動画チャプター生成は設定画面の最後に配置。動画上の開始時刻は時・分・秒それぞれ1桁でも入力可能（例: `1:2:3`）。生成時は動画時間が1時間未満なら時間の桁を省略して `mm:ss`、1時間以上なら `hh:mm:ss` で出力する
  - 保存済みの1P/2Pを使用し、未設定時はオーバーレイと同じ上側1P・下側2Pの扱い。上部の「プレイヤー表示」の「エイリアス名を使う」設定を基準の試合情報・生成テキストともに反映し、エイリアス未設定の場合は元の名前を使う
  - 各 Set の最新の配信開始記録を使うため、再配信前の時刻は復元しない。画面を開く際にローカルデータを読み込み、配信開始記録の再読み込みも可能
  - 「テキスト生成」を押すたびに最新の保存データを読み直し、その時点のプレイヤー表示設定・エイリアス名・1P/2P・配信開始記録で生成し直す
  - カテゴリ1・2・3のチェックボックスで、プレイヤー名の後ろに付ける保存済みアイテムを選択できる（初期状態は未選択）。同一カテゴリ内は `,`、カテゴリ間は `/` で区切り、`プレイヤー名(アイテムA,アイテムB/アイテムC)` の形式でカテゴリ順に表示する。空のカテゴリは省略し、該当アイテムがない場合は括弧を付けない。変更後は「テキスト生成」で再生成する
  - 「勝敗を表示する」をONにすると、確定した勝者に `〇`、敗者に `●` を付け、そのすぐ右に取得ゲーム数を表示する（例: `〇2 プレイヤーA vs ●0 プレイヤーB`）。直接勝敗指定・DQ・ゲーム数不明の場合は記号のみ、未確定の試合は名前のみを表示する。初期状態はOFF。エイリアス名・カテゴリ表示と併用でき、変更後は再生成する
  - オープニング文・勝敗表示・表示カテゴリ・基準の試合・動画上の開始時刻は、変更時にイベント単位で端末のローカル設定へ自動保存し、画面を開き直した際やアプリ再起動後に復元する。生成テキストは保存せず、エイリアス名の設定は既存のプレイヤー表示設定を引き続き使用する
  - 「全配信開始時刻をクリア」で、確認後に選択中イベントの全 Set の配信開始時刻をローカルメタデータから削除する。試合結果・プレイヤー情報・他イベントは変更しない。生成テキストと動画上の開始時刻もリセットする。配信中の Set の記録は、停止・再開するまで再作成しない
  - 基準として選択した試合の配信開始日時は、端末の現地時刻で直接修正し「記録日時を修正」でメタデータへ保存できる。動画上の開始時刻は保持し、次の生成時に修正後の日時で計算する。「配信記録のクリア」は確認後にその試合だけの記録を削除し、チャプター生成対象から外す（DQ等で配信しなかった試合向け）。個別クリア時は基準選択と動画上の開始時刻をリセットする。どちらも試合結果・他の試合の記録は変更せず、生成済みテキストは再生成が必要。日時入力欄と両ボタンは1行に配置する

### 4. OBS オーバーレイ

- 現在の試合を OBS 上で表示する overlay 画面のWebサーバを内蔵
- プレイヤー名、セット情報、取得ゲーム数
- name fit mode で truncate / shrink を切り替え
- set info の表示/非表示切り替え
- full stop モードの切り替え
- overlay preview とテスト表示に対応
- PC・モバイルで対戦カード確定済み・結果未確定の set を配信開始すると、スコア入力の有無やプールの編集ロックに関係なく、最新の開始時刻（UTC）をローカルメタデータの `setStreamStarts` に保存。停止後の再開や別 set からの切り替えで更新し、配信中のスコア・名前更新、停止、テスト配信では更新しない（start.gg への送信は行わない）

### 5. アイテムリスト

- カテゴリに属するアイテム候補を追加・編集・削除
- 大会管理設定と紐づけて使用
- event ごとに必要な選択候補を差し替え可能

### 6. プレイヤーリストとカード出力

- event 内の entrant を一覧表示
- 「スナップショット&メタデータ設定」の「エイリアス名を使う」を有効にすると、一覧・カードプレビュー・カード出力にもプレイヤーのエイリアス名を適用（未設定の場合は元の名前を表示）
- 暗号化された playerId を生成して保持
- プレイヤーカードのプレビュー
- 2次元コード付きカードの出力
  - メールなどで直接カードを送付する用途
- A4 向けの画像生成に対応
  - 印刷して切り取って配布する用途

### 7. メッセージ / 呼び出しシステム

- ローカルネットワーク上で機能別の宛先（`destination`）を持つメッセージを送受信。呼び出しは `call_list`、外部編集・スコア関連は `bracket` 宛て
- 送信者名・8 桁ユーザー ID・ネットワークデバイスを設定
- 汎用メッセージ、メッセージ画面、スレッド管理、メッセージボックスの強制クリアは廃止。各機能から直接送信する
- ブラケットのプレイヤー呼び出しは確認後、メッセージ画面を経由せず呼び出しリスト宛てにブロードキャスト送信
- 呼び出しはスレッド履歴と分離して未解決の状態のみ保存。自分の呼び出しと他端末の呼び出しを分けて表示し、同一のイベント・フェーズ・プール・セット・プレイヤーの再受信で受信時刻を更新
- 自分の呼び出しを解決するとブロードキャストで通知し、受信端末も該当する他端末の呼び出しを削除
- 自分／他端末は8桁ユーザーIDで区別し、区分ごとに同じ対象を1件へ統合。他端末は発行元が異なっても再受信で更新し、いずれかの発行元からの解決通知で削除する。自分の呼び出しは他端末の解決では削除しない。未解決の呼び出しがある間はユーザーIDを変更しないこと
- 「呼び出しの再送要求」は他端末の呼び出しを一旦クリアしてブロードキャスト送信。各端末は自身の未解決の呼び出しを、元の発行時刻を保って要求元にだけ返信
- 外部報告申請は `bracket` 宛てにブロードキャスト。受信側はプールごとに最後に受信した申請を表示し、プール選択欄にも申請ありを表示
- 各プールで受理／拒否を応答でき、応答は `bracket` 宛てに申請者だけへ個別送信。受理時はプールをロックして外部報告者を設定し、申請者へプール全同期を要求する。申請者側は現時点で応答に自動反応しない
- 通常の外部報告は `bracket` 宛てにブロードキャスト。受信時の編集ロック・承認済み報告者・対象set／参加者・確定情報の連番による受理ルールは従来どおり
- 欠番補完・全同期の要求と再送は要求元への個別送信を維持。外部報告の処理済みIDを専用保存し、再起動や重複受信による再処理を防ぐ
- 呼び出しと外部報告はメッセージ画面・スレッド履歴から独立。呼び出しは専用保存だけを読み込み、既存のメッセージ履歴からは復元しない。保存済み外部報告データの初回取り込みは継続
- 他端末の呼び出しカードをクリックしてPLAYER ID認証・QR読取付きのDQ申請を開く。呼び出し元の端末にのみ `bracket` 宛てで送信し、送信・受信時に専用保存された未解決の呼び出しと認証情報を検証する
- 受信したDQ申請は対象プールで表示。DQ内容を確認して試合結果を確定した時点で処理済みにする（開く・キャンセルするだけでは消えない）
- 不要になったDQ申請は、呼び出しリストのDQ申請確認画面・対象プールの受信DQ申請一覧の「DQ申請を破棄」で破棄できる。呼び出しと試合結果は変更せず、破棄状態は再起動後も維持する
- リモートDQ申請は呼び出しを解決してから試合結果を確定する。確定後に呼び出し解決確認ダイアログは表示しない
- 外部報告者の連絡先は専用保存し、報告処理後・再起動後も同期要求に利用する。既存の旧メッセージファイルは削除しない
- 通信はUDPのため到達・順序は保証されない。取りこぼしや表示の不整合は再送要求で再構築
- 設定からローカル通信を停止可能（停止中は主に閲覧のみ）

## 画面構成

サイドバーから以下の画面を開けます。

- **スナップショット**: start.gg から event を取得してスナップショットを作成し、保存済みスナップショットの検索・選択・インポート・エクスポートを行う
- **スナップショット&メタデータ設定**: 選択中スナップショットの更新、event alias、運営ルール、プレイヤー情報を管理する。サイドバーの選択中スナップショット欄から開く
- **ブラケット**: phase / pool の選択、結果入力・報告、プールごとの外部報告申請への受理／拒否、DQ申請の確認を行う
- **オーバーレイ**: OBS へ配信する試合情報を管理する
- **アイテムリスト**: プレイヤー情報入力に使うアイテム候補を管理する
- **呼び出しリスト**: 未解決の呼び出しを確認し、自分の呼び出しの解決や他端末の呼び出しに対するDQ申請を行う
- **プレイヤーリスト**: entrant 情報を確認し、プレイヤーカードを出力する
- **設定**: start.gg API トークン以外の送信者・ネットワーク・同期設定を行う

## 基本フロー

> 前提: 対象の start.gg tournament / event が先に作成されていて、seed が確定している必要があります。ローカル側で event を新規作成したり seed を補完する機能はありません。

1. start.gg の developer 設定で API トークンを発行する。
2. 「スナップショット」画面でトークンを保存し、tournament slug を入力して event 一覧を取得する。
3. 対象 event を選択し、必要ならアプリ内表示用の alias を入力してスナップショットを作成する。event を選び直すと alias 入力はクリアされる。
4. 保存済みスナップショット一覧から対象 event を選択する。別 PC で作成したデータは JSON をインポートして利用できる。
5. サイドバーの選択中スナップショット欄から「スナップショット&メタデータ設定」を開き、alias、1P/2P 決定方法、カテゴリ設定、必要なプレイヤー情報を整える。start.gg 側の変更を取り込む場合はスナップショットを更新する。
6. 「ブラケット」で phase / pool を選び、試合の1P/2Pやスコアを入力する。set をクリックすると詳細を開き、Ctrl+クリックで配信表示を切り替え、Alt+左クリックで配信を完全停止する。
7. ローカル結果を確認して確定し、確定済み set を一括報告する。未確定の作業結果はローカルに保持される。
8. 複数クライアントで連絡機能を使う場合は、「設定」で送信者名・8桁ユーザー ID・ネットワークデバイスを設定して保存する。必要に応じて「ローカル通信を行わない」を OFF にする。
9. 必要に応じてオーバーレイ、メッセージ / 呼び出し、アイテムリスト、プレイヤーリストを利用する。

## 保存先

Tauri の app_data_dir 配下に `settings` と `snapshots` のフォルダを作成して保存します。

`settings`:

- startgg-token.txt
- last-slug.txt
- last-snapshot-selection.json
- item-lists.json
- event-mgmt-settings.json
- sender-profile.json
- generic-messages.json
- call-list.json（未解決の呼び出しと受信時刻。メッセージ履歴の強制クリアとは独立）
- bracket-messages.json（プールごとの最新の外部報告申請・未処理報告・処理済みID。メッセージ履歴の強制クリアとは独立）

`snapshots`:

- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-snapshot.json (start.gg取得時点の復元用原本)
- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-pristine.json
- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-graph.json (Bracketの作業用グラフ)
- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-meta.json

補足:

- 取り込み単位は event です。
- 同一 tournament で複数 event を持つ場合でも、slug と eventId の組み合わせで個別に管理します。
- ローカル meta には、イベント設定、プレイヤー設定、1P/2P 配置、保留中結果、playerId 生成用情報が含まれます。
- start.gg 上の slug と eventId は安全なファイル名へ変換して保存されます。

## OBS オーバーレイの使い方

- 「オーバーレイ」画面で overlay の状態を確認する
- 現在の試合を選んで overlay と同期する
- 文字サイズや name fit mode を調整する
- set info の表示有無や fully stopped モードも切り替えられる
- 外部ブラウザで http://127.0.0.1:42691/overlay を開けば表示確認ができる

## ローカルスナップショットの扱い

大会スナップショットと原本スナップショットは event ごとに個別ファイルで保持されます。

同じ tournament の複数 event を別々に選択・更新・削除できます。「スナップショット」画面では、alias / tournament 名 / event 名で検索でき、JSON ファイルへのエクスポートとインポートでスナップショットを別クライアントへ移せます。

スナップショットからの復元では、現在の Seed の並び順を維持して対象範囲のスコア・未報告結果を戻します。「全体」を復元する場合のみ、確認ダイアログで「Seedの並び順を維持して復元」または「Seedの並び替えも破棄して復元」を選択できます。現在 Pool・現在 Phase のロック中 Pool の復元では Seed の並び替えは破棄されません。

## ローカルネットワークでの連携

メッセージと呼び出しリストを複数クライアントで利用する場合は、各クライアントの「設定」で送信者名、重複しない 8 桁ユーザー ID、利用するネットワークデバイスを設定して保存します。IP とサブネットマスクは選択したデバイスから反映されます。クライアント間で到達可能なネットワークを選び、ファイアウォール等の通信を妨げる設定がないことを確認してください。

呼び出し・外部報告はブロードキャスト、DQ申請・申請への応答・同期の再送は相手端末への個別送信です。通信を使わない場合は設定の「ローカル通信を行わない」を有効にしてください。この設定中は各機能の送受信・操作が制限されます。

## 技術スタック

- Frontend: React + TypeScript + Vite
- Desktop: Tauri v2
- Backend: Rust
- GraphQL Client: graphql-client
- State / persistence: Tauri file I/O + localStorage

npm install

npm run build

## 実装上の注意

- start.gg のスキーマ変更時は、GraphQL 定義と `src-tauri/src/graphql` 配下の定義を更新してください。
- start.gg のイベント作成・seed 確定はこのアプリの前提条件です。
- ROUND ROBIN、phaseGroup、phase間進出の処理手順は [docs/phase-group-progression.md](docs/phase-group-progression.md) を参照してください。
- イベント管理設定やアイテムリスト、メッセージ履歴はアプリのローカル保存に依存するため、再インストール時はデータのバックアップに注意してください。
- Player ID や DQ 申請は本人確認のための検証情報として扱うため、適切な運用に合わせて利用してください。

## 進行中のアプリの主な運用パターン

- event ごとに snapshot を作成またはインポートし、必要な場合は更新して進行管理する
- bracket で phase / pool ごとの対戦状況を確認し、結果をローカルで確定してから start.gg にまとめて報告する
- OBS オーバーレイで試合情報を配信画面へ展開する
- 設定済みのクライアント間でメッセージ、呼び出し、各種申請・報告を連携する
- アイテムリストとプレイヤーカードで運営補助・記録管理を行う
