# savakan-gg

start.gg で運用する大会を、イベント単位でローカルにミラーし、進行管理・試合結果入力・一括報告・オーバーレイ連携・連絡運用まで一括で扱う Tauri アプリです。

## 概要

サバ管ggは、start.gg のイベントデータをベースとして使いながら、ローカルで追跡・検証・補助運用を行うためのアプリケーションです。  

主な目的は次のとおりです。

- 録画・配信ソフト向けのライブオーバーレイを組み込み、現在の試合情報と勝ち数を表示する
  - 対戦カードをオーバーレイ表示する際のプレイヤー名入力等の煩雑さを軽減
- アイテムリスト・プレイヤー情報・配信者向けメッセージと呼び出し管理を同一イベント内で扱う
  - 他のクライアントと連携して呼び出し情報を共有、表示可能

## 主要機能

### アイテムの自由記入

- 各カテゴリの「使用リスト」で「自由記入」を選ぶと、事前にリストを用意せずテキストを入力できます。「追加」またはEnterで項目を追加し、通常と同じ保存操作で記録します。カテゴリごとの件数制限・重複可否も適用されます。
- 自由記入はカテゴリ1〜3で個別に利用でき、既存リストとも併用できます。記録はカテゴリ別に保存され、アイテムリストは自動作成されません。
- アイテムリストエディタの「自由記入を取り込み」で、読み込み中のイベントの保存済み自由記入カテゴリを1つ選べます。取り込みプレビューで内容を確認でき、記録された1アイテムをそのまま1項目として、前後の空白・空項目・重複を除去します。区切り文字による分割は行いません。
- 取り込んだ項目は編集欄へ重複を除いて追加します。取り込みだけではリストを保存せず、名前や項目を編集して「作成」または「更新」で保存します。
- 自由記入カテゴリではCSVからの未登録アイテムも受け付け、保存済みの内容は利用統計・オーバーレイ・YouTubeチャプターにも反映されます。

### ローカルeventのフェーズ設定

- イベントの作成方法（start.gg取り込み／ローカルevent）は前回の選択を保存し、次回起動時にも復元します。ローカルeventのデフォルトイベント名は `YYYY-MM-DD Local Event` です。
- ローカルeventでは、前後の空白を除いたtournament名・event名の組が同じイベントを重複作成できません。既存のローカルeventがある場合は上書き警告を表示し、承認した場合だけ既存IDを維持して参加者・ブラケット・試合結果・配信開始記録を置き換えます。キャンセル時は変更しません。既に同名のローカルeventが複数ある場合は、不要なイベントを削除してから作成してください。start.gg由来のイベントはこの名前による重複判定から除外します。
- フェーズ数はtournament名・event名・エイリアス名と同じ行の右端で、1桁用のコンパクトな選択欄から指定します。
- 参加人数は直接入力せず、この画面の参加者リスト（2〜512人）から決まります。先にカテゴリの使用リスト・選択数・重複可否・全体選択数を設定して適用し、「参加登録」からプレイヤー名とアイテムを登録します。一覧をクリックして再編集でき、選択中の参加者を削除することもできます。登録順を初期Seed順として、登録名・アイテム選択・カテゴリ設定を作成したイベントに保存します。
- CSV取り込みダイアログの「event名の先頭に日付を付ける」をONにすると、イベント名を `YYYY-MM-DD ファイル名（拡張子なし）` にします。日付は取り込み時のローカル日付で、初期値はOFFです。確定前にイベント名を確認できます。
- CSVは繰り返し取り込めます。参加者の編集中もCSV取り込みを開けますが、取り込みを確定すると編集中の内容を破棄し、参加者リストを置き換えます。キャンセルした場合は編集内容を維持します。
- 「参加者を全員クリア」で参加者一覧と編集中の参加者をクリアできます。カテゴリ設定・イベント名は維持します。
- カテゴリ設定の変更後も参加者の編集・追加が可能です。参加者の選択・追加・保存時に未適用の設定を適用し、対象外アイテムを除去した状態から手動修正できます。不正な設定がある場合は先に設定を修正してください。
- 「アイテム登録は必須」（初期値ON）の場合のみ、選択数の下限を満たすまで参加者保存・イベント作成を無効にします。OFFなら選択未完了でも登録・作成できます。上限・重複可否・使用リストの制約は維持します。
- 「参加登録」の右の「CSV取り込み」からUTF-8のCSV（先頭行はカラム名）を選び、プレイヤー名と有効なカテゴリ1〜3のカラムを割り当てて取り込めます。カテゴリ設定は別途「設定の適用&保存」を押さなくても、現在編集中の使用リスト・選択条件を取り込みに使用し、取り込み成功時に参加者と一緒に適用します。不正なカテゴリ設定がある場合は取り込めません。参加者はCSVの行順で既存リストを置き換え、ファイル名（`.csv`なし）をevent名に設定します。キャンセル・読み込みエラー時は変更しません。カテゴリ欄は改行・カンマ区切りで、対象リストに完全一致するアイテムのみ設定します。未一致や割り当てなしは未設定とし、選択数の条件を満たさない参加者は取り込み後に編集できます。引用符・引用符内の改行・カンマ、UTF-8 BOMに対応します。
- 「アイテム選択カテゴリの設定」は初期状態で折りたたまれています。見出しをクリックすると「設定の適用&保存」までの設定欄を開閉できます。参加者数は「参加者一覧(X 人)」の見出しにまとめて表示します。
- 各カテゴリの使用リストは、フォント選択と同じ入力・候補一体型UIで選択できます。入力するとリスト名・カテゴリ名の部分一致で絞り込みます（英字の大文字・小文字は区別しません）。↑↓とEnterで選択でき、「未選択」で解除できます。Escや欄外への移動で検索を取り消し、元の選択表示に戻ります。イベント作成とメタデータ設定の両方で利用できます。
- CSV取り込み時もカテゴリ設定の変更・適用時も、対象リストに存在しないアイテムは除去して未設定扱いにします。有効なアイテムや他カテゴリの選択は残し、除去後は手動で再編集できます。それ以外の選択数・重複条件の変更で新条件を満たさなくなった参加者は選択をクリアします。未完了の参加者は一覧に色と「選択未完了」で表示します。編集中の参加者や未適用のカテゴリ変更がある間はイベント作成できません。
- フェーズは1〜3個設定でき、「Phase X (参加人数)」をフェーズ名入力欄の左に表示します。参加人数は前フェーズからの進出人数に連動します。カラム名は最上段に1回だけ表示し、各入力欄と横位置をそろえます。狭い画面では設定一覧を横スクロールできます。
- 最終フェーズがシングルエリミネーションなら3位決定戦、ダブルエリミネーションなら5位決定戦を設定できます。フェーズ数にかかわらず表示し、各プールの人数がそれぞれ4人未満・8人未満の場合はチェックボックスを無効化します。前のフェーズからの進出人数も判定に反映します。
- ダブルエリミネーションの各フェーズで「GF Reset」の有無を設定できます（初期値ON）。OFFではLosers側がGrand Finalで勝ってもリセット試合を作らず、その試合で決着します。作成済みイベントおよびstart.ggイベントは従来の挙動を維持します。
- 各フェーズの入力・決定戦・GF Reset・総当たりの勝利条件は1行にまとめ、狭い画面では横スクロールします。「進出人数」は各プールからの進出人数で、入力欄のツールチップでも確認できます。
- 人数不足の決定戦はラベルもグレーアウトして操作できません。作成時にも条件を再確認し、チェックONかつ各プールの必要人数を満たす場合だけ決定戦を作成します。
- 作成後は「スナップショット&メタデータ設定」の「Seedをシャッフル」で初期Seed順を変更できます。自動確定した不戦勝は試合開始済みとみなさず、シャッフル後の進出先を再計算します。実際の試合が開始・結果入力済みの場合は変更できません。「スナップショット時に戻す」で登録順に戻せます。
- ローカルeventのSet Identifierは、表示される可能性がある試合だけにプール内でAから連続して割り当てます。BYEとの対戦や、その進出先で構造上必ず不戦勝になる対戦には割り当てません。後続フェーズの未確定参加者同士の対戦は採番対象です。

### オーバーレイのカスタマイズ

- プレビュー領域内でCtrl＋マウスホイールを使うと25〜400%の範囲で拡大縮小できます。上方向で拡大、下方向で縮小し、倍率スライダーも連動します。通常のホイールはページスクロールのままで、コンポーネントやキャンバスのドラッグ中は倍率を変えません。「全体に合わせる」で倍率・パンをリセットできます。
- プレビュー上でShiftを押しながらコンポーネントをドラッグすると、最初の移動方向に応じて水平または垂直に固定します。Shiftを離すと自由移動に戻り、再度押すと方向を選び直します。複数選択時も全項目が同じ軸に沿って移動します。リサイズとキャンバスのパンには適用しません。移動は従来どおり確定／キャンセルの対象で、ズーム操作は出力データを変更しません。
- 新規追加する全種類のコンポーネントは、プリセット画面の中央に配置します。位置は整数に丸め、コンポーネントより画面が小さい方向は座標0にします。表示倍率・パンは初期座標に影響せず、複製時は元の位置を維持します。文字色・背景色のAlpha初期値は255（不透明）です（文字色は白、背景色は黒）。既存プリセットや複製・インポートしたコンポーネントの透明度、デフォルトレイアウトの透明な重ね合わせは維持します。
- テキスト・数値・アイテムの文字位置は「水平揃え」（左／中央／右）と「垂直揃え」（上／中央／下）を独立して指定できます。新規コンポーネント・新規プリセットは水平・垂直とも中央揃えが初期値です。改行・折り返しを含む文字全体をコンポーネント枠内に配置します。変更は「確定」で反映し、保存・複製・エクスポート／インポートでも維持します。垂直位置を持たない旧プリセットは従来どおり通常は上寄せ、プレートとイベントエイリアスの組み込み装飾は中央寄せで表示します。デフォルトレイアウトの配置は変更しません。
- 「オーバーレイ」タブ下部で、アプリ全体で共有するレイアウトプリセットを作成・複製・削除できます。「新規作成」で複製時と同じ形式のダイアログを開き、画面の幅・高さを指定して「この解像度で作成」で編集を開始します（初期値1920×1080、各辺1〜16384pxの整数）。「キャンセル」またはEscキーでは編集内容を変えずに閉じます。解像度は作成後に変更できません。
- テキスト・数値・アイテムには「はみ出たら改行」「はみ出たら縮小」のチェックボックスがあります。ONの処理を上から順に適用し、改行後も幅・高さに収まらない場合に縮小します。縮小の下限は設定した文字サイズの50%（最小1px）です。それでも収まらなければ末尾を「…」で省略します（「…」自体も入らない極小の枠では空表示）。手動の改行は維持し、フォント読み込み後も再計算します。時計・画像は対象外です。新規作成は改行ON・縮小OFF、旧プリセットの未設定値は従来の折り返しを引き継ぎます。「セット・ラウンド情報」もこの設定に従います。デフォルトを複製したプレイヤー名は改行OFF・縮小ONです。配信テスト設定の「プレイヤー名を縮小表示」は廃止し、設定はコンポーネント単位で保存・複製・エクスポート／インポートします。デフォルトの配信画面のプレイヤー名は縮小後に省略する固定動作です。
- 「編集するプリセット」のリストは、未保存の変更があるプリセット名の先頭に `*` を表示します。新規作成・複製・インポートした未保存のプリセットや、現在編集中の未確定の変更も対象です。確定済みの未保存変更は選択を切り替えても表示を維持し、保存済みの内容に戻ると印が消えます。未確定の変更は「保存」だけでは保存されないため、その変更が残っている間は印も残ります。名前自体には `*` を追加しません。
- プリセット操作の「複製」で専用の複製ダイアログを開きます。複製元を確認し、元の解像度を初期値として複製先のサイズを指定して、「この解像度で複製」で作成します。幅と高さは連動し、片方を指定すると複製元のアスペクト比を基準にもう片方を整数値へ調整します。上限に達する場合は両方を範囲内に収めます。「キャンセル」またはEscキーでは編集内容を変えずに閉じます。新規作成時は、任意の縦横比を設定できるよう幅・高さを個別に指定できます。
- 複製するコンポーネントの位置・サイズ・文字サイズは同じ倍率で拡大縮小し、レイアウト全体を中央に配置します。整数化で縦横比に差が出ても全体が収まる倍率を使い、余白を均等に配置します。位置・サイズ・文字サイズの端数は整数値に丸め、サイズは1〜16384px、位置は0〜16384px、文字サイズは1〜1000pxに収めます。元から画面外にはみ出したコンポーネントは切り詰めません（保存形式の上限を超える場合を除く）。元のプリセットや、画像・数値・表示状態・重なり順は変更しません。「キャンセル」では複製しません。
- プレビュー右側の「コンポーネント一覧」の下にある「新規追加」（「複製」の左）で作成ダイアログを開き、種別（テキスト／数値／アイテム／画像）と識別用のコンポーネント名を指定します。名前は1〜256文字で、オーバーレイに出す内容とは独立しています。作成後も名前を編集でき、保存・エクスポート・インポート時に維持します。名前を持たない旧形式のデータは、既存の表示情報から識別名を補って読み込みます。
- 「アイテム」はテキストと同じ位置・サイズ・フォント・色を設定できるコンポーネントです。「対象プレイヤー」で1P／2P、「表示情報」で「スナップショット&メタデータ設定」のイベントに設定されたカテゴリ1〜3を選び、各プレイヤーがそのアイテムリストから選択して保存した内容だけを選択順に表示します。リストの全候補を表示するものではありません。重複可のカテゴリでは重複も維持します。「区切り文字」は初期値 ` / `、最大256文字で、空欄や改行も指定できます。カテゴリ未設定・アイテム未選択・配信停止時は空表示です。保存済みの選択を変更すると配信表示も更新し、1P／2Pの入れ替えにも追従します。対象・カテゴリ・区切り文字はプリセットの保存・複製・エクスポート・インポートでも維持します。
- テスト配信設定には、1P／2Pそれぞれカテゴリ1〜3の「ダミーアイテム」入力欄があります。例: `アイテムA アイテムB アイテムA`。半角・全角スペースなどの空白で区切り、入力順・重複を維持します。空欄は未選択として扱います。テスト配信開始時と配信中の変更時に反映し、停止中のカスタマイズプレビューも同じ入力を使います。ダミー入力は実際のプレイヤーの保存済み選択や本配信には影響しません。画面上の結合方法はアイテムコンポーネントの「区切り文字」に従います。
- 「時計」は表示端末のローカル日時を毎秒更新するテキスト形式のコンポーネントです。プレビューと配信画面でそれぞれの端末の時刻・タイムゾーンを使い、固定テキストと同様に位置・サイズ・フォント・文字色・背景色・水平／垂直揃えを設定できます。「表示フォーマット」は1〜256文字で、初期値は `YYYY-MM-DD HH:mm:ss`。`YYYY/YY`（年）、`MM/M`（月）、`DD/D`（日）、`HH/H`（24時間）、`hh/h`（12時間）、`mm/m`（分）、`ss/s`（秒）、`A/a`（AM/PM・am/pm）、`dddd/ddd`（英語の曜日名・略称）、`d`（日曜0〜土曜6）を使えます。2文字の指定はゼロ埋めし、それ以外の文字はそのまま表示します。トークン文字をそのまま表示する場合は `[文字列]` で囲みます（例: `YYYY年MM月DD日 [時刻] HH:mm:ss`）。フォーマット変更も「確定／キャンセル」の対象で、保存・複製・エクスポート・インポート時に維持します。完全停止中は他のコンポーネントと同様に非表示です。
- コンポーネント一覧は「表示・名称・タイプ・表示情報」の表形式です。先頭のチェックボックスで表示・非表示を切り替えます。この変更は「確定」を待たずプリセットへ反映し、ファイル保存は「保存」で行います。別のコンポーネントを編集中でも選択や編集内容を保ったまま操作でき、「キャンセル」でも表示状態は戻しません。名称は識別名、タイプはテキスト／数値／アイテム／時計／画像、表示情報はデータのソース種別（アイテムの場合は対象プレイヤーとカテゴリ、時計の場合は「現在の日時」、画像の場合は読み込んだファイル名）です。画像未設定やファイル名を持たない旧データは「-」で表示します。画像のファイル名も保存・エクスポート・インポート時に維持します。
- 一覧の行から選択して編集でき、非表示の項目も選択できます。一覧の上の行ほど手前に重なります。行をドラッグ＆ドロップし、挿入位置を示す青い線の場所に並べ替えます。名称にフォーカスしてAlt＋↑/↓でも1行ずつ移動できます。並べ替えはドラッグした1行だけが対象で、ドロップ成功時にその行を単独選択します。未確定の変更がある状態で別の項目を選ぶと、変更を確定して切り替える・破棄して切り替える・選択をキャンセルする、のいずれかを選ぶダイアログを表示します。中止したドラッグでは表示順・選択・編集中の内容を変更しません。既存データやエクスポート形式の配列順は引き続き背面から前面の順です。プレビュー上のドラッグで移動、選択枠の右下でサイズ変更できます。位置・サイズは数値でも指定でき、一覧下部で複製・削除できます。プレビュー上の選択と一覧の選択は連動します。
- 一覧・プレビューでCtrl＋クリックすると、選択を追加・解除できます。選択順を保ち、最初に選択した項目を編集欄に表示します。最初の項目を選択解除すると、次に選択した項目へ切り替わります。通常のクリックは単独選択です。選択済みの項目をドラッグすると、複数選択を保って相対位置を変えずに一括移動します。明暗2本の破線による最小矩形で選択全体を囲み、非表示の選択項目も範囲・移動に含めます。枠の線幅はプレビュー倍率にかかわらず一定です。
- 複数選択中はリサイズハンドルを非表示にします。編集欄・複製・削除は最初の選択項目だけを対象にします。一括移動・サイズ統一・センタリングは未確定の変更として扱い、「確定」で全選択項目に反映、「キャンセル」でまとめて戻します。未確定の変更がある状態で選択を変える場合は、ダイアログで変更を確定・破棄するか、選択をキャンセルできます。保存・エクスポート・適用先には確定済みの内容だけを渡します。選択状態自体は保存しません。
- コンポーネントの「確定」「キャンセル」は一覧下部のボタン群の一番下に配置し、プレビューの近くで変更を反映・取り消しできます。編集欄下部には重複して配置しません。複数選択時は対象件数と「一括確定」「一括キャンセル」を表示し、一括移動・サイズ統一・センタリングなどの変更を、非表示の選択項目も含めてまとめて反映・取り消しできます。未確定の変更がなければボタンを無効にします。入力エラーがある場合は反映せず、該当する入力欄を示します。確定後に端末へ保存するには、上部の「保存」を押してください。
- 一覧下部の「サイズ統一」で、最初に選択したコンポーネントの現在の幅・高さに、選択中の他のコンポーネントを合わせます。位置やフォントサイズは変更せず、非表示の選択項目も対象です。2件以上の選択で利用できます。
- 一覧下部の「センタリング」は、選択全体を囲む最小矩形の中心をプリセット画面全体の中心に合わせます。「水平」「垂直」「両方」（初期値）を排他的に選択し、単独選択でも利用できます。全選択項目を同じ整数の移動量で動かすため、相対位置を保ち、整数座標から新たな小数座標は作りません。奇数サイズなどで中心が一致しない場合のずれは最大0.5pxです。移動後の座標が保存可能な0〜16384の範囲を超える場合は、エラーを表示して全項目の移動を中止します。表示倍率・パンは計算に影響せず、未確定の位置・サイズも計算に含めます。
- 表示順の変更（行のドラッグ＆ドロップ・Alt＋↑/↓）は「確定」を待たずプリセットに反映します。「キャンセル」や選択変更でも表示順は戻りません。端末への保存は上部の「保存」で行います。位置・サイズ・フォントなどの未確定の編集内容は、並べ替えだけでは確定されません。
- コンポーネントの編集（画像の差し替え・プレビュー上の移動やサイズ変更を含む）は、まずプレビューと一覧だけに反映します。「確定」でプリセットに反映し、「キャンセル」で編集前に戻します。別のコンポーネントを選択した場合は、ダイアログで未確定の変更を確定するか破棄するかを選べます。編集対象のプリセットを切り替えた場合は未確定の変更を破棄します。複製は確定済みの内容を使います。端末への保存・エクスポートには確定済みの内容だけを使うため、編集後は「確定」してから上部の「保存」を押してください。
- Windows版でも一覧の行を並べ替えられるよう、Tauriのネイティブなファイルドロップ処理を無効にし、WebView内のドラッグ＆ドロップを使います。画像やプリセットの読み込みは、従来どおりファイル選択から行えます。
- コンポーネント名・X座標・Y座標・幅・高さ・背景色は同じ行にまとめています（狭いウィンドウでは折り返します）。文字色・背景色は省スペースな色見本と16進カラーコードのボタンで表示し、クリックすると独自のカラーピッカーを開きます。色の平面をドラッグするか、色相・彩度・明度のスライダーで選択し、同じポップアップ内で透明度スライダー・Alpha値（0〜255の整数）・カラーコード（`#RRGGBB`／`#RRGGBBAA`）も指定できます。スライダーはキーボードでも調整できます。0は完全透明、255は不透明で、市松模様で透過具合を確認でき、Alpha値を0にしても選択したRGB色は保持します。「閉じる」・Esc・欄外クリックでポップアップを閉じても変更は未確定のままで、一覧下部の「確定」「キャンセル」で反映・取り消します。空欄や範囲外・小数のAlpha値、不正なカラーコードでは確定できず、閉じたピッカーも入力エラー時に再表示します。保存・複製・エクスポート／インポートに8ビットの値をそのまま維持し、従来の6桁カラーコードと背景の`transparent`も引き続き読み込めます。
- コンポーネント名とフォント名の入力欄は、どちらも最大18remの同程度の幅に抑えています（名前の保存上限は従来どおり256文字）。フォント名・文字サイズ・文字色（Alpha値）・文字揃え・太字は同じ行に配置し、右側の項目をフォント名の直後から左詰めで並べます（狭いウィンドウでは折り返します）。フォント名は絞り込みとドロップダウンを一体化した選択専用の欄です。入力した文字で候補を大文字・小文字を区別せず部分一致で絞り、空欄なら全候補を表示します。候補をクリック、または↑↓とEnterで選ぶと、正式なフォント名で入力欄を置き換えます。検索文字自体は設定に反映せず、候補以外の名前や複数フォントの新規直接入力はできません。Escや欄外への移動では検索を取り消し、設定中のフォント名に戻します。候補を開き直すと全候補を表示します。画面にはフォント名を表示し、保存時はインストール済みフォント名にCSS用の引用符・エスケープを付け、汎用ファミリーはそのまま設定します。候補には、この端末の標準フォントディレクトリから取得したフォントと汎用ファミリーを表示します。候補件数を表示し、一致しなければその旨を示します。過去のプリセットに含まれる候補外の指定は、別の候補を選ぶまで保持します。フォントの選択は未確定の編集として扱い、「確定／キャンセル」の対象です。一覧は初回に取得して再利用します。フォント追加後はアプリを再起動すると候補に反映されます。一覧取得に失敗した場合はエラーを表示し、汎用ファミリーの選択は利用できます。録画・配信ソフトを別端末で使う場合は、その端末にも同じフォントが必要です。
- カスタマイズプレビューは幅・高さの両方に収まるよう、アスペクト比を保って全体表示します。表示領域はウィンドウの高さの60%・最大600pxに制限し、縦長や高解像度でも画面からはみ出しません。「プレビュー倍率」で全体表示を100%として25〜400%に拡大縮小できます。左ドラッグは「キャンバスを移動」がONのときだけ表示位置を移動し、OFFのときはコンポーネントの移動・サイズ変更専用です。余白の左ドラッグでは移動しません。マウス中ボタンはON/OFFにかかわらずキャンバスを移動します。「全体に合わせる」で倍率・表示位置をリセットします。プリセット切り替え時も全体表示に戻ります。これらは編集画面だけの表示設定で、プリセットの解像度・コンポーネント座標・オーバーレイ出力は変更しません。
- テキストは1P/2Pのプレイヤー名、セット／ラウンド情報、Phase／Pool／Set名、ラウンド名、イベント名・エイリアス、固定テキストから選択できます。フォント名・文字サイズ・太字・色・文字揃え・背景も変更できます。
- 数値は1P/2Pのスコア、または直接入力する固定数値（負数・小数も可）から選択できます。現時点では数字で表示し、将来の別表現に備えてテキストとはタイプを分けています。既存のスコア用テキストは、名前・位置・サイズ・装飾を保って数値タイプへ自動移行します。固定数値も保存・エクスポート・インポートに含まれます。
- 画像は4MB以下のPNG・JPEG・GIF・WebPに対応し、縦横比を維持してコンポーネント枠内に表示します。フォントは名前で指定するため、録画・配信ソフトを動かす端末にも同じフォントをインストールしてください。
- 編集内容は「保存」で端末に保存します。テスト配信設定の先頭にある「適用するプリセット」は編集対象とは独立しており、保存済みのプリセットを選ぶと即座にオーバーレイ出力へ適用します。未保存の新規プリセットは候補に含めず、未保存・未確定の編集内容も適用しません。適用先を変えても編集中の内容は保持します。適用中のプリセットを編集して保存した場合は出力にも反映します。タブを離れる前に保存してください。保存済みプリセットと適用状態はアプリの再起動後も復元します。
- 「適用するプリセット」で「デフォルト」を選ぶと、従来の表示に戻ります。従来の表示設定（名前縮小・中央情報・イベントエイリアスの表示）はデフォルト用です。カスタム表示では各コンポーネントの設定を使い、「完全停止」では画像・固定テキスト・固定数値を含めすべて非表示にします。適用中のプリセットを削除して保存した場合もデフォルトへ戻ります。
- 編集対象に「デフォルト」を選ぶと、閲覧専用のプレビューとコンポーネント一覧を表示します。拡大縮小やキャンバス移動は利用できますが、内容・表示状態・重なり順は編集できません。プリセット操作の「複製」で、組み込みの1920×1080レイアウトを元にプレイヤー名・スコア・中央情報・イベントエイリアスと枠の装飾を編集可能なプリセットへコピーできます。組み込みのレイアウト自体は変更しません。コピー後の「装飾スタイル」を「装飾なし」にすると、通常のテキスト表示へ切り替えられます。
- テキスト・数値・アイテム・時計の「装飾スタイル」は「装飾なし」「プレート」「グラス」から選べます。「プレート」は従来の組み込み装飾で、プレイヤー名などの角丸パネル・枠線・文字の縁取りを使います。既存の装飾はそのまま維持し、「プレート」を選び直した場合は表示情報に応じた装飾を使います。「グラス」は角丸の半透明パネル・細い白枠・すりガラスのぼかし・柔らかな影を組み合わせます。背景には選択中の背景色を使い、Alpha値にスタイルの透過率（36〜62%）を掛けます。文字色・Alpha値・太字・水平／垂直揃えを維持し、通常のテキストと同じく改行・折り返しにも対応します。すりガラスのぼかしは、同じブラウザページ内で背後に描画された内容に作用します（録画・配信ソフトの別ソースには作用しません）。スタイル変更も「確定／キャンセル」の対象で、保存・複製・エクスポート・インポート時に維持します。
- 「エクスポート(単体)」または「エクスポート(全体)」で画像込みのJSONを保存できます。「プリセットをインポート」は既存データを上書きせず、新しいIDで追加します。インポート後は保存してください。最大64プリセット・各128コンポーネント、JSONは32MB以下です。
- ブラウザソースに対応した録画・配信ソフト（OBS Studioなど）で利用できます。オーバーレイのURLは従来と同じです。録画・配信ソフト側のブラウザソースの幅・高さも適用中プリセットの解像度に合わせてください。

### 表示言語

- PCアプリの「設定」にある「言語 / Language」で、日本語と English を切り替えられます。初期値は日本語です。
- 言語の選択は端末のローカル設定に保存され、再起動後も維持されます。
- スマートフォン入力画面でも言語を選択できます。PCとは独立してブラウザーごとに保存されます。
- 大会名・イベント名・プレイヤー名・エイリアス・アイテム名・自由入力メッセージなどのデータは翻訳・書き換えません。オーバーレイに表示する実際の名前も維持します。
- 外部サービス・通信相手からのメッセージや、翻訳が定義されていない診断情報は原文を表示します。
- 翻訳文言はPC側では `src/i18n/` の辞書にまとめています。画面に新しい固定文言を追加する際は、日本語と英語の両方を追加してください。

### 1. 大会・イベント同期

- tournament slug から event 一覧を取得
- direct 指定で tournament slug + event slug を引く
- event 単位でローカルスナップショットを作成・選択・更新・削除
- スナップショットを JSON ファイルにエクスポート / インポートして、別クライアントへ共有
- 同一 tournament 内で複数 event を持つ運用に対応

### 2. 大会管理

- event alias の設定
  - 日本語名のエイリアスが設定可能
- 1P/2P 判定ルールの選択
- カテゴリごとのアイテムリスト、選択数制限、重複可否の管理
  - start.ggで未対応のゲームでも使用キャラの履歴などが保持できる
  - 使用率の表示も可能
- 変更内容をイベント単位で保存
- プレイヤー情報の「プレイヤーエイリアス名を保存」と「アイテムの選択状態を保存」は独立しています。エイリアス名だけの保存は、アイテムの選択数が下限・上限を満たしていなくても可能です。どちらの保存も、もう一方の保存済み内容や未保存の入力は変更しません。

### 3. ブラケット管理

- phase / pool を切り替えて試合を表示
- Elimination はラウンド別のブラケット、ROUND ROBIN は対戦マトリックスと現在順位を表示
- 表示倍率を変更可能（ROUND ROBIN の standings は倍率の影響を受けない）
- slot ごとに 1P/2P・スコア・勝者をローカル保存
- 保留中結果と確定済み結果を分けて管理
- winner 判定が start.gg と衝突した場合は競合解消を行える
- 一括報告により複数 set をまとめて反映
- pool ごとのスコア編集ロックや、外部報告者へのスコア報告を利用可能
- 「スナップショット&メタデータ設定」の「動画チャプター生成」で、選択中イベントの配信済み Set を開始時刻順に出力できる。配信開始順の一覧から時刻合わせの基準にする試合を選択できる（初期選択は最初の試合）。基準の試合の対戦プレイヤー（1P vs 2P）・Phase／Pool／Set・ラウンド・配信開始記録時刻を表示する。動画上でその試合を探し、開始時刻（`hh:mm:ss` または `mm:ss`）を入力して右側の「テキスト生成」を押すと、記録時刻との差から1P・2Pプレイヤー名を含むチャプター文字列を生成する。動画時間が1時間未満なら時刻は `mm:ss`、1時間以上なら `hh:mm:ss` で表示する。基準の試合を変更すると入力時刻をリセットする。入力やエイリアス名の設定変更、記録の再読み込み後は再度生成する
  - 計算された再生時刻が10秒未満の試合（負の時刻を含む）は、時刻の代わりに `(未記録)` と表示する。10秒ちょうどから通常の時刻を表示し、`00:00` のオープニング行は維持する
  - `00:00` のテキストは変更可能（初期値「オープニング」）。「テキスト生成」の右にある「テキストをコピー」で生成結果をクリップボードへコピーできる
  - 動画チャプター生成は設定画面の最後に配置。動画上の開始時刻は時・分・秒それぞれ1桁でも入力可能（例: `1:2:3`）。生成時は動画時間が1時間未満なら時間の桁を省略して `mm:ss`、1時間以上なら `hh:mm:ss` で出力する
  - 保存済みの1P/2Pを使用し、未設定時はオーバーレイと同じ上側1P・下側2Pの扱い。上部の「プレイヤー表示」の「エイリアス名を使う」設定を基準の試合情報・生成テキストともに反映し、エイリアス未設定の場合は元の名前を使う
  - 各 Set の最新の配信開始記録を使うため、再配信前の時刻は復元しない。画面を開く際にローカルデータを読み込み、配信開始記録の再読み込みも可能
  - 「テキスト生成」を押すたびに最新の保存データを読み直し、その時点のプレイヤー表示設定・エイリアス名・1P/2P・配信開始記録で生成し直す
  - カテゴリ1・2・3のチェックボックスで、プレイヤー名の後ろに付ける保存済みアイテムを選択できる（初期状態は未選択）。チェックボックスは縦に3つ並び、設定済みの場合はカテゴリ名とリスト名を併記する。同一カテゴリ内は `,`、カテゴリ間は `/` で区切り、`プレイヤー名(アイテムA,アイテムB/アイテムC)` の形式でカテゴリ順に表示する。空のカテゴリは省略し、該当アイテムがない場合は括弧を付けない。変更後は「テキスト生成」で再生成する
  - 「勝敗を表示する」をONにすると、確定した勝者に `〇`、敗者に `●` を付け、そのすぐ右に取得ゲーム数を表示する（例: `〇2 プレイヤーA vs ●0 プレイヤーB`）。直接勝敗指定・DQ・ゲーム数不明の場合は記号のみ、未確定の試合は名前のみを表示する。初期状態はOFF。エイリアス名・カテゴリ表示と併用でき、変更後は再生成する
  - オープニング文・勝敗表示・表示カテゴリ・基準の試合・動画上の開始時刻は、変更時にイベント単位で端末のローカル設定へ自動保存し、画面を開き直した際やアプリ再起動後に復元する。生成テキストは保存せず、エイリアス名の設定は既存のプレイヤー表示設定を引き続き使用する
  - 「全配信開始時刻をクリア」で、確認後に選択中イベントの全 Set の配信開始時刻をローカルメタデータから削除する。試合結果・プレイヤー情報・他イベントは変更しない。生成テキストと動画上の開始時刻もリセットする。配信中の Set の記録は、停止・再開するまで再作成しない
  - 基準として選択した試合の配信開始日時は、端末の現地時刻で直接修正し「記録日時を修正」でメタデータへ保存できる。動画上の開始時刻は保持し、次の生成時に修正後の日時で計算する。「配信記録のクリア」は確認後にその試合だけの記録を削除し、チャプター生成対象から外す（DQ等で配信しなかった試合向け）。個別クリア時は基準選択と動画上の開始時刻をリセットする。どちらも試合結果・他の試合の記録は変更せず、生成済みテキストは再生成が必要。日時入力欄と両ボタンは1行に配置する

### 4. オーバーレイ

- 現在の試合を録画・配信ソフト上で表示する overlay 画面のWebサーバを内蔵
- プレイヤー名、セット情報、取得ゲーム数
- name fit mode で truncate / shrink を切り替え
- set info の表示/非表示切り替え
- full stop モードの切り替え
- overlay preview とテスト表示に対応
- PC・モバイルで対戦カード確定済み・結果未確定の set を配信開始すると、スコア入力の有無やプールの編集ロックに関係なく、最新の開始時刻（UTC）をローカルメタデータの `setStreamStarts` に保存。停止後の再開や別 set からの切り替えで更新し、配信中のスコア・名前更新、停止、テスト配信では更新しない（start.gg への送信は行わない）

### 5. アイテムリスト

- カテゴリに属するアイテム候補を追加・編集・削除
- 大会管理設定と紐づけて使用
- event ごとに必要な選択候補を差し替え可能

### 6. プレイヤーリストとカード出力

- event 内の entrant を一覧表示
- 「スナップショット&メタデータ設定」の「エイリアス名を使う」を有効にすると、一覧・カードプレビュー・カード出力にもプレイヤーのエイリアス名を適用（未設定の場合は元の名前を表示）
- 暗号化された playerId を生成して保持
- プレイヤーカードのプレビュー
- 2次元コード付きカードの出力
  - メールなどで直接カードを送付する用途
- A4 向けの画像生成に対応
  - 印刷して切り取って配布する用途

### 7. メッセージ / 呼び出しシステム

- ローカルネットワーク上で機能別の宛先（`destination`）を持つメッセージを送受信。呼び出しは `call_list`、外部編集・スコア関連は `bracket` 宛て
- 送信者名・8 桁ユーザー ID・ネットワークデバイスを設定
- 汎用メッセージ、メッセージ画面、スレッド管理、メッセージボックスの強制クリアは廃止。各機能から直接送信する
- ブラケットのプレイヤー呼び出しは確認後、メッセージ画面を経由せず呼び出しリスト宛てにブロードキャスト送信
- 呼び出しはスレッド履歴と分離して未解決の状態のみ保存。自分の呼び出しと他端末の呼び出しを分けて表示し、同一のイベント・フェーズ・プール・セット・プレイヤーの再受信で受信時刻を更新
- 自分の呼び出しを解決するとブロードキャストで通知し、受信端末も該当する他端末の呼び出しを削除
- 自分／他端末は8桁ユーザーIDで区別し、区分ごとに同じ対象を1件へ統合。他端末は発行元が異なっても再受信で更新し、いずれかの発行元からの解決通知で削除する。自分の呼び出しは他端末の解決では削除しない。未解決の呼び出しがある間はユーザーIDを変更しないこと
- 「呼び出しの再送要求」は他端末の呼び出しを一旦クリアしてブロードキャスト送信。各端末は自身の未解決の呼び出しを、元の発行時刻を保って要求元にだけ返信
- 外部報告申請は `bracket` 宛てにブロードキャスト。受信側はプールごとに最後に受信した申請を表示し、プール選択欄にも申請ありを表示
- 各プールで受理／拒否を応答でき、応答は `bracket` 宛てに申請者だけへ個別送信。受理時はプールをロックして外部報告者を設定し、申請者へプール全同期を要求する。申請者側は現時点で応答に自動反応しない
- 通常の外部報告は `bracket` 宛てにブロードキャスト。受信時の編集ロック・承認済み報告者・対象set／参加者・確定情報の連番による受理ルールは従来どおり
- 欠番補完・全同期の要求と再送は要求元への個別送信を維持。外部報告の処理済みIDを専用保存し、再起動や重複受信による再処理を防ぐ
- 呼び出しと外部報告はメッセージ画面・スレッド履歴から独立。呼び出しは専用保存だけを読み込み、既存のメッセージ履歴からは復元しない。保存済み外部報告データの初回取り込みは継続
- 他端末の呼び出しカードをクリックしてPLAYER ID認証・QR読取付きのDQ申請を開く。呼び出し元の端末にのみ `bracket` 宛てで送信し、送信・受信時に専用保存された未解決の呼び出しと認証情報を検証する
- 受信したDQ申請は対象プールで表示。DQ内容を確認して試合結果を確定した時点で処理済みにする（開く・キャンセルするだけでは消えない）
- 不要になったDQ申請は、呼び出しリストのDQ申請確認画面・対象プールの受信DQ申請一覧の「DQ申請を破棄」で破棄できる。呼び出しと試合結果は変更せず、破棄状態は再起動後も維持する
- リモートDQ申請は呼び出しを解決してから試合結果を確定する。確定後に呼び出し解決確認ダイアログは表示しない
- 外部報告者の連絡先は専用保存し、報告処理後・再起動後も同期要求に利用する。既存の旧メッセージファイルは削除しない
- 通信はUDPのため到達・順序は保証されない。取りこぼしや表示の不整合は再送要求で再構築
- 設定からローカル通信を停止可能（停止中は主に閲覧のみ）

## 画面構成

サイドバーから以下の画面を開けます。

- **スナップショット**: start.gg から event を取得してスナップショットを作成し、保存済みスナップショットの検索・選択・インポート・エクスポートを行う
- **スナップショット&メタデータ設定**: 選択中スナップショットの更新、event alias、運営ルール、プレイヤー情報を管理する。サイドバーの選択中スナップショット欄から開く
- **ブラケット**: phase / pool の選択、結果入力・報告、プールごとの外部報告申請への受理／拒否、DQ申請の確認を行う
- **オーバーレイ**: 録画・配信ソフトへ出力する試合情報を管理する
- **アイテムリスト**: プレイヤー情報入力に使うアイテム候補を管理する
- **呼び出しリスト**: 未解決の呼び出しを確認し、自分の呼び出しの解決や他端末の呼び出しに対するDQ申請を行う
- **プレイヤーリスト**: entrant 情報を確認し、プレイヤーカードを出力する
- **設定**: start.gg API トークン以外の送信者・ネットワーク・同期設定を行う

## 基本フロー

> 前提: 対象の start.gg tournament / event が先に作成されていて、seed が確定している必要があります。ローカル側で event を新規作成したり seed を補完する機能はありません。

1. start.gg の developer 設定で API トークンを発行する。
2. 「スナップショット」画面でトークンを保存し、tournament slug を入力して event 一覧を取得する。
3. 対象 event を選択し、必要ならアプリ内表示用の alias を入力してスナップショットを作成する。event を選び直すと alias 入力はクリアされる。
4. 保存済みスナップショット一覧から対象 event を選択する。別 PC で作成したデータは JSON をインポートして利用できる。
5. サイドバーの選択中スナップショット欄から「スナップショット&メタデータ設定」を開き、alias、1P/2P 決定方法、カテゴリ設定、必要なプレイヤー情報を整える。start.gg 側の変更を取り込む場合はスナップショットを更新する。
6. 「ブラケット」で phase / pool を選び、試合の1P/2Pやスコアを入力する。set をクリックすると詳細を開き、Ctrl+クリックで配信表示を切り替え、Alt+左クリックで配信を完全停止する。
7. ローカル結果を確認して確定し、確定済み set を一括報告する。未確定の作業結果はローカルに保持される。
8. 複数クライアントで連絡機能を使う場合は、「設定」で送信者名・8桁ユーザー ID・ネットワークデバイスを設定して保存する。必要に応じて「ローカル通信を行わない」を OFF にする。
9. 必要に応じてオーバーレイ、メッセージ / 呼び出し、アイテムリスト、プレイヤーリストを利用する。

## 保存先

Tauri の app_data_dir 配下に `settings` と `snapshots` のフォルダを作成して保存します。

`settings`:

- startgg-token.txt
- last-slug.txt
- last-snapshot-selection.json
- item-lists.json
- event-mgmt-settings.json
- sender-profile.json
- generic-messages.json
- call-list.json（未解決の呼び出しと受信時刻。メッセージ履歴の強制クリアとは独立）
- bracket-messages.json（プールごとの最新の外部報告申請・未処理報告・処理済みID。メッセージ履歴の強制クリアとは独立）

`snapshots`:

- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-snapshot.json (start.gg取得時点の復元用原本)
- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-pristine.json
- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-graph.json (Bracketの作業用グラフ)
- <tournamentIdを安全化した文字列>-<slugを安全化した文字列>-<eventIdを安全化した文字列>-<event名slug>-meta.json

補足:

- 取り込み単位は event です。
- 同一 tournament で複数 event を持つ場合でも、slug と eventId の組み合わせで個別に管理します。
- ローカル meta には、イベント設定、プレイヤー設定、1P/2P 配置、保留中結果、playerId 生成用情報が含まれます。
- start.gg 上の slug と eventId は安全なファイル名へ変換して保存されます。

## オーバーレイの使い方

- 「オーバーレイ」画面で overlay の状態を確認する
- 現在の試合を選んで overlay と同期する
- 文字サイズや name fit mode を調整する

- 外部ブラウザで http://127.0.0.1:42691/overlay を開けば表示確認ができる

## ローカルスナップショットの扱い

大会スナップショットと原本スナップショットは event ごとに個別ファイルで保持されます。

同じ tournament の複数 event を別々に選択・更新・削除できます。「スナップショット」画面では、alias / tournament 名 / event 名で検索でき、JSON ファイルへのエクスポートとインポートでスナップショットを別クライアントへ移せます。

start.ggからの作成・更新・同期では、参加者のSkill Tierを取得し、ローカルで未設定の参加者の初期値として採用します。取り込み後の再取得では、ローカルのSkill Tier（未設定に戻した場合も含む）を上書きしません。「スナップショット&メタデータ設定」で参加者を選び、「Skill Tierを最新の取り込み値に戻す」を押すと、その参加者のSkill Tierだけを最後に取り込んだ値へ復元できます。start.gg側が未設定なら未設定へ戻ります。復元値は再取得ごとに更新され、アプリの再起動やJSON共有後も保持されます。Skill Tier自体をstart.ggへ書き戻すことはありません。

スナップショットからの復元では、現在の Seed の並び順を維持して対象範囲のスコア・未報告結果を戻します。「全体」を復元する場合のみ、確認ダイアログで「Seedの並び順を維持して復元」または「Seedの並び替えも破棄して復元」を選択できます。現在 Pool・現在 Phase のロック中 Pool の復元では Seed の並び替えは破棄されません。

## ローカルネットワークでの連携

メッセージと呼び出しリストを複数クライアントで利用する場合は、各クライアントの「設定」で送信者名、重複しない 8 桁ユーザー ID、利用するネットワークデバイスを設定して保存します。IP とサブネットマスクは選択したデバイスから反映されます。クライアント間で到達可能なネットワークを選び、ファイアウォール等の通信を妨げる設定がないことを確認してください。

呼び出し・外部報告はブロードキャスト、DQ申請・申請への応答・同期の再送は相手端末への個別送信です。通信を使わない場合は設定の「ローカル通信を行わない」を有効にしてください。この設定中は各機能の送受信・操作が制限されます。

## 開発・起動コマンド

Node.js 22.12以上の22系、24系、または26以上と、現行のstable Rustを使用してください（Node.jsの対応範囲はVitestに合わせています）。フロントエンドはTypeScript 7・Vite 8・React用Viteプラグイン6を使用します。依存関係のバージョンはnpmとCargoのロックファイルで管理します。

npm ci

npm run build

## 実装上の注意

- デスクトップ版ではTauriのdialogプラグインが`window.confirm`を非同期処理に置き換えます。確認が必要な操作は必ず`await window.confirm(...)`で結果を待ち、キャンセル時には削除・上書き・送信などを実行しないでください。通常のブラウザーの同期confirmでも同じ書き方で動作します。
- start.gg のスキーマ変更時は、GraphQL 定義と `src-tauri/src/graphql` 配下の定義を更新してください。
- start.gg のイベント作成・seed 確定はこのアプリの前提条件です。
- ROUND ROBIN、phaseGroup、phase間進出の処理手順は [docs/phase-group-progression.md](docs/phase-group-progression.md) を参照してください。
- イベント管理設定やアイテムリスト、メッセージ履歴はアプリのローカル保存に依存するため、再インストール時はデータのバックアップに注意してください。
- Player ID や DQ 申請は本人確認のための検証情報として扱うため、適切な運用に合わせて利用してください。

## 進行中のアプリの主な運用パターン

- アイテムリストとプレイヤーカードで運営補助・記録管理を行う
